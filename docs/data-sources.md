| U.S. Census Geocoder                             | Transient address normalization and coordinates            | Implemented server-side using current benchmark/vintage requests, a timeout, no-store caching, schema validation, and no address logging                                 | Medium        | Monitor service behavior and validate hard Nevada boundary cases before broad public release    |

The Census documentation explicitly notes that coordinates may be interpolated from TIGER address ranges. A successful geocode therefore cannot be treated as proof that a structure exists or as the sole authority near district boundaries.

The normalized boundary artifact is generated by `npm run data:boundaries` from `data/sources/nevada-boundaries-2021.manifest.json`. The generator also unions the four official congressional polygons and applies a documented display-only simplification to produce the statewide map outline; district lookup continues to use the unsimplified source geometry. Generation fails on checksum, feature-count, district-sequence, geometry-type, or Nevada-coordinate-bound changes. See decision record `0002-geographic-boundary-pipeline.md`.

## Discovery exit criteria

- Representative fixtures exist for success, ambiguity, missing fields, schema changes, and historical updates.
- External identifiers are namespaced and stable enough for idempotent imports.
- Each adapter has an owner, cadence, parser version, health signal, and last-known-good behavior.
- Publication stops on unexpected schemas, topology failures, count changes, or reconciliation errors.
- Exact residential addresses are absent from fixtures and diagnostic output.
